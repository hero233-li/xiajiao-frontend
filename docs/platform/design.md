# 知途个人管理平台设计规范

## 信息架构与导航

统一入口 `/` 只展示自学/健身两个空间入口与今天的两项简洁行动。自学路径 `/study`，健身路径 `/fitness`，账号偏好 `/settings`。管理员入口仍由现有角色权限控制，位于账号区；普通用户不能看到或访问管理工作台。旧 `/zikao` 深链接通过受保护的兼容路由保留参数和锚点跳转。

桌面使用固定228px侧栏、78px顶栏和最大1280px内容区。侧栏固定提供个人首页、空间切换与账号设置。每个空间显示自己的导航；课程内再有能力驱动的二级导航。手机760px以下使用顶部空间选择器与横向可滚动标签栏，空间切换和返回首页在同一位置。桌面/手机均通过同一账号访问，页面业务不会在设备间分叉。

首页使用两个大型空间入口，之后是无卡片的今日行动列表；自学首页为主行动、清单、科目列表和考试侧栏；阅读界面为进度工具栏、目录导航、文章正文与操作栏。健身今天用一条目标摘要、打卡统计和训练/食谱双栏，再提供记录操作与简洁实际摘要。训练按7天浏览，计划和实际并列；食谱同样分列计划和实际；历史以日历和趋势为主。手机双栏顺序堆叠，训练周浏览变为4列与3列。

## 基础视觉

| 用途 | 值 |
|---|---|
| 基础背景 | #F5F7FA |
| 内容表面 | #FFFFFF |
| 主文字 | #233447 |
| 次级文字 | #6B7785（主要解释文字） |
| 分隔线 | #DDE3E9 |
| 自学主色 | #315C91 |
| 健身主色 | #317565 |
| 自学浅底 | #EDF3FB |
| 健身浅底 | #EEF5F1 |
| 强错误 | 现有danger token，文字与图标共同提示 |

无全屏渐变，无动态装饰。空间入口的书本/哑铃仅作为低对比的业务识别符。表面用细边框和8–12px圆角分区，常规内容没有悬浮投影。列表优先细分隔线，不把每个条目都变成独立卡片。

字体优先 PingFang SC、Microsoft YaHei、系统无衬线。平台标题桌面30px/手机25px，区块标题18px/16px，操作和元信息12–14px，长内容14–15px、行高1.8–1.9。中文标题不会强制英文字母间距；英文空间标识只作为低优先级眉题。数字带明确单位，未知用“未知”或“尚未记录”，不以0替代。字号按阅读用途建立层级，表单文字保持清晰。

4px基础网格：8px紧密字段、12px操作间距、16–20px列表行、24px常规分区、32–48px页面留白。桌面侧栏对齐内容起点；手机左右20px。输入与按钮保留足够点击区域，避免手机横向溢出。紧凑偏好只减少间距，不缩小重要文字。

## 交互与状态

主按钮用于当前明确提交/开始动作；次按钮用于编辑与创建入口；文字按钮用于复制、查看与低频操作。删除使用说明具体对象的确认对话。保存时禁用重复提交并显示处理中。表单字段有显式label和单位，选填字段留空即未知；类型变化清空无关训练字段。营养数据展开编辑，明确用户自行填写。

对话框采用现有可访问Modal能力：焦点锁定、返回触发按钮、Escape关闭、背景inert。编辑草稿离开提醒；冲突保留输入并要求重新读取，禁止静默覆盖。网络失败提供重试；摘要和详情错误不会冒充空数据；无内容提供明确创建入口。登录失效沿用全局刷新与回跳机制；管理员权限仍由后端校验。

体重图只绘制真实日期点，只有相邻自然日期连接，空日期留缺口。均值和样本数量来自后端。日历用文字/图形共同区分打卡、部分记录、过去未打卡、今天待办、未来计划和休息安排，不单靠颜色。历史统计表明分母或无计划，不显示虚构达成日期和效果因果。

## 主要页面截图

`evidence/` 的截图由真实Spring Boot、MySQL隔离库和浏览器交互生成。截图中的“测试”训练、食谱和账号属于自动验收专用数据，不会写入现有业务库。包含个人首页、自学首页/阅读、目标、训练/完整周、饮食、体重、打卡历史、账号设置，以及手机核心页面。

## 第一周计划编辑

新增绿色侧边说明条作为轻量入口，避免在今天页面堆叠7天详细内容。弹窗通过Day 1～7与「训练步骤 / 三餐与加餐」切换：默认按步骤、餐次阅读，切换到编辑时复用真实计划表单。手机日标签横向滚动，内容与操作条保持在屏幕内；底部整周保存按钮常驻。

保存前可编辑全部7天，保存后回到对应日期计划继续修改。来源粗估与确定数值分开展示；实际完成、营养统计和打卡继续以真实记录为准。
